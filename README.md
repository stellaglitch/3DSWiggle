# 3DSWiggle — wigglegram camera for Nintendo 3DS

Takes a photo with both outer cameras at the same time,  lets you pick the
focal point between the two, and then saves that as a "wigglegram"!
The GIF loops between frame 1 and frame 2, with an adjustable **120 ms** delay between
the two photos. You can also add crossfade frames between them to make it look smoother.

## Controls

**Camera screen**

| Button | Action |
|---|---|
| A | Take the photo (both cameras) |
| SELECT | Live preview: Camera 1 / Camera 2 / Wiggle |
| Y | Gallery |
| START | Quit |

**Gallery** (plays your saved GIFs on the top screen, newest first)

| Button | Action |
|---|---|
| D-Pad ◀ ▶ or L / R | Previous / next GIF |
| X | Delete this GIF (A to confirm, B to cancel) |
| B | Back to the camera |

**Adjust screen** (photo on the top screen; the bottom screen works as a touch pad for it)

| Button | Action |
|---|---|
| Touch | Pick the focal point. Frame 2 auto-aligns so this point stays fixed. |
| D-Pad | Fine-tune the alignment 1 px at a time |
| Circle Pad ◀ ▶ | Timing between the two photos, 40–500 ms in 10 ms steps (default 120) |
| L / R | Crossfade frames between the photos. 0 = classic two-frame wiggle. The maximum depends on timing: 120 ms allows 5, 240 ms or more allows 11. |
| SELECT | View: Wiggle / Onion skin / Frame 1 / Frame 2 |
| A | Save GIF |
| B | Retake |
| START | Quit |

Onion skin overlays both frames at 50%. The focal point looks sharp and
everything else looks doubled, which makes fine alignment easy.

## How it works (`source/wiggle.c`)

1. **Alignment.** A mean-removed SAD template search finds where your focal point
   lands in frame 2. Frame 2 is shifted by that offset, and the output is cropped
   to the area both frames cover.
2. **Crossfade frames.** Each in-between is a plain blend of the two aligned
   photos, `(1−t)·frame1 + t·frame2`. The key frames stay exactly the original
   photos. The core also still contains an experimental depth-based morph
   (`wg_compute_disparity` / `WG_MODE_MORPH`). The app no longer uses it, but
   the PC tests still cover it.
3. **GIF.** A median-cut 256-colour global palette is built from all frames. The
   frames get 4×4 ordered dithering, which stays still from frame to frame. Then
   LZW encoding, a NETSCAPE infinite-loop block, and frame order
   `0,1..n+1,n..1` with centisecond delays that add up to 120 ms per transition.

## Building

The build runs in the official `devkitpro/devkitarm` container image, using
podman or docker. Under Windows, run these from WSL. You don't need a local
devkitPro install.

One time, build the CIA packaging tools, makerom and bannertool, from source into `tools/bin`:

```bash
bash tools/build_cia_tools.sh
```

Then build both `3DSWiggle.cia` and `3DSWiggle.3dsx`:

```bash
bash build.sh
```

To build only the `.3dsx` (doesn't need the CIA tools):

```bash
bash build.sh all
```

If you have devkitPro installed locally, plain `make` / `make cia` also work.

The icon, banner and banner jingle live in `assets/`, generated by
`python3 tools/make_assets.py`. Edit the script or drop in your own
`icon.png` (48×48), `banner.png` (256×128) and `audio.wav` (under 3 s).
CIA permissions and the title ID (`0xF9A1E`) are set in `app.rsf`.

## Installing

You need a 3DS / 2DS / New 3DS with custom firmware. The 2DS models have the same
two outer cameras.

- **CIA (recommended):** copy `3DSWiggle.cia` to the SD card and install it with
  FBI (or another CIA installer). It then shows up on the HOME Menu like a
  normal app.
- **3DSX:** copy `3DSWiggle.3dsx` to `sd:/3ds/` and launch it from the Homebrew Launcher.

## Testing the core on a PC

The image pipeline is plain C. The test builds a synthetic 3-layer stereo pair,
checks the disparity, alignment and timing, writes sample GIFs, and decodes them
with an independent decoder:

```bash
gcc -O2 -Isource tests/pc_test.c source/wiggle.c -o pc_test -lm && ./pc_test .
```
